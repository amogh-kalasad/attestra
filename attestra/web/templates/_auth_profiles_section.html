Authenticated security testing — test roles

Define the roles you will exercise (viewer, user, manager, admin, and any custom roles). Prefer separate test accounts per role. Choose how the scanner authenticates: form login, header token, cookie, or SSO bootstrap.

Secrets (passwords, tokens, session values) must go to the dedicated credential endpoint — never into ordinary engagement notes, rules of engagement, or free-text metadata. This form stores only non-secret metadata and posts the secret field to that endpoint as an opaque reference.

Do not paste production passwords here. Use disposable test accounts authorized in the signed rules of engagement. Secrets are stored as references only and are never shown again in the UI.
Examples: viewer, user, manager, admin.
CSS selector only — not the password value.
